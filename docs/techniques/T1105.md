# T1105 – Ingress Tool Transfer via certutil

**LOLBin:** `certutil.exe`  **Rule:** [`proc_creation_win_certutil_download.yml`](../../rules/windows/process_creation/proc_creation_win_certutil_download.yml)

> This is a worked example to show the format. Replace the bracketed parts with what you actually observe in your lab.

## How attackers use it
`certutil` is a signed Microsoft tool for managing certificates. Its `-urlcache` and `-verifyctl` options will fetch any file from a URL, which lets an attacker download a second-stage payload without bringing their own downloader. It has appeared in many ransomware and APT intrusions documented by the DFIR Report and CISA advisories.

## Detection logic
The rule requires three things: the binary is certutil (by path **or** by `OriginalFileName`), the command line contains a download verb (`urlcache` or `verifyctl`), and it contains a URL scheme. Requiring the URL keeps `certutil -urlcache` (which just lists the cache) from firing, so the fixture `tests/fixtures/benign/baseline.jsonl` includes that case on purpose.

## Evasion attempts
| Attempt | Bypassed v1? | Fix |
|---|---|---|
| Copy to `C:\Users\Public\cu.exe` and run | Yes: v1 only checked the path | Match `OriginalFileName: CertUtil.exe` (PE header survives renaming) |
| `-verifyctl` instead of `-urlcache` | Yes | Added `verifyctl` |
| `/URLCACHE` uppercase | No, Sigma matching is case-insensitive | n/a |

## Blind spots
- An attacker could patch the PE header to change `OriginalFileName`; Sysmon's `Hashes` field or an image-load allowlist would catch that.
- Using a different downloader (`bitsadmin`, `curl.exe`, PowerShell `Invoke-WebRequest`) isn't covered here; see the T1197 rule.
- Correlating with Sysmon Event ID 3 (certutil making a network connection) would give a higher-confidence signal.
